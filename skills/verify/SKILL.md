문서 경로는 PLAN.md의 매핑을 따르고, 매핑이 없으면 아래 기본 경로를 사용한다. 과제 지정 양식이 같은 역할이면 REQUIREMENTS.md·DECISIONS.md 대신 그 파일을 사용한다.


범위를 지정하지 않으면 최근 변경을 검증한다. AGENTS.md의 검증·도구 경계를 따른다.

1. 정상 경로와 중요한 예외 경로를 고르고 가장 피해가 큰 실패 하나를 짧게 알린 뒤 진행한다. 업무상 기대값을 알 수 없을 때만 질문한다.
2. PLAN.md의 관련 검증을 실행한다. 테스트가 없으면 핵심 규칙을 확인하는 최소 테스트를 추가한다. 변경 영향이 없는 통과 항목은 재실행하지 않는다.
3. 서버는 실제 포트에서 curl로 확인한다. 사용자에게 플랫폼 Browser의 포트·경로와 직접 확인할 동작 2~3개를 안내한다. 응답 성공과 화면 확인을 구분하고 서버를 유지한다. UI 자동화는 사용하지 않는다.
4. 중요 오답을 구현 함수와 별개인 기준값·손 계산·원본 집계로 직접 검산한다. 사용자 수동 실행을 기본 조건으로 삼지 않는다. 기준값의 출처도 남긴다.
5. 확정 입력과 기대값 비교를 우선한다. 핵심 규칙의 오류 검출력이 여전히 불명확하고 시간 여유가 있을 때만 변형 검증을 선택한다. work/verify-*에 최소 파일을 복사하고 해당 규칙 하나를 틀리게 바꿔 테스트 실패를 확인한다. 원본을 바꾸지 않는다. 기존 버그의 실패→수정→통과 증거가 있으면 그것으로 충분하다.
6. 실패를 발견하면 원인·변경 범위를 알리고 요청 범위 안에서 수정한 뒤 관련 항목만 재검증한다. 범위 변경이나 기대값 결정이 필요할 때만 질문한다. 약 10분을 썼으면 핵심 경로 영향·새 근거·대안을 비교해 계속 조사할지 결정한다.

PLAN.md에 `항목 / 명령 또는 수동 동작 / 기대값·근거 / 실제값 / 통과·실패·미검증`을 남긴다. 수동 동작은 사용자 확인 전까지 미검증이다. 시간 부족·접근 불가도 이유와 함께 남기며 통과로 바꾸지 않는다. 최종 응답은 핵심 결과·남은 위험만 보고한다.
