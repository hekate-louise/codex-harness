name: diagnosing-bugs
description: 재현되지 않거나 반복해서 막히는 버그·성능 문제를 짧은 재현과 가설 검증으로 진단한다.
---

일상적인 오류는 바로 원인·범위를 확인해 고친다. 막힌 문제는 약 10분을 조사 판단 시점으로 삼아 아래 흐름을 수행한다. AGENTS.md의 도구·자료 경계를 우선한다.

1. 사용자 증상에 맞는 작은 실패 입력과 명령을 찾는다. 테스트·CLI·curl을 우선하고 UI 자동화·외부 전송·플랫폼 프로세스 변경은 하지 않는다. 화면 조작만 가능한 경우 사용자에게 수동 단계 최대 3개를 안내한다. 필요하면 scripts/hitl-loop.template.sh를 참고하되 대기형 스크립트를 필수로 실행하지 않는다.
2. 재현 결과·에러·관련 코드만 읽고 가능성 높은 원인 1~2개를 세운다. 재현을 만들 수 없어도 코드 근거로 제한된 조사를 할 수 있지만 원인 확정과 검증 완료를 주장하지 않는다. 모든 입력을 최소화하거나 가설 개수를 채우느라 시간을 쓰지 않는다.
3. 한 번에 한 원인을 검증한다. 로그는 필요한 위치만 임시 표시하고 키·토큰·개인정보를 출력하지 않는다. 성능 문제는 좁은 입력으로 전후 시간을 비교하며 무제한 부하·대량 반복을 피한다.
4. 요청 범위의 최소 수정을 하고 원래 실패와 관련 정상 경로를 다시 실행한다. 실제 버그를 잡는 회귀 테스트를 남기고 관찰한 실패→수정→통과를 PLAN.md에 기록한다. 같은 근거의 변형 검증을 추가로 반복하지 않는다.
5. 임시 로그와 본인 테스트 프로세스를 정리한다. 약 10분 후 해결하지 못하면 근거·핵심 경로 영향·우회안을 비교한다. 필수 기능을 막고 새 근거가 있으면 예산을 조정해 계속 조사하고, 그렇지 않으면 다른 작업으로 전환한다. 미해결 Must는 기록한다. 플랫폼 오류는 사용자에게 문제 신고를 안내한다.

각 가설마다 사용자 승인을 받지 않는다. 기대값·범위 결정이 꼭 필요할 때만 질문하고 실패를 숨기거나 테스트 기대값을 임의로 바꿔 통과시키지 않는다.
