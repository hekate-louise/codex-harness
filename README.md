# Codex 작업 하네스 — SK하이닉스 AI 해커톤

제공된 Codex에서 180분 안에 문제 정의·구현·검증·제출을 끝내기 위한 작업 원칙과 스킬이다. GPT/Codex가 필요한 지침만 읽고 요청 범위의 작업을 이어가도록 구성했다. 플랫폼 실제 안내와 과제 README가 우선한다.

## 설치
제공 작업 공간의 과제 루트에서 실행한다. 공개 저장소 반입은 허용되지만 개인 PC 파일 업로드·Git Push·과제 자료 외부 전송은 금지다.

```bash
git clone https://github.com/hekate-louise/codex-harness work/codex-harness
bash work/codex-harness/install.sh .
```

설치기는 AGENTS.md, REQUIREMENTS.md, DECISIONS.md, PLAN.md와 .agents/skills 아래 스킬 12개를 복사한다. 기존 파일·스킬 폴더는 보존하며 업데이트하지 않는다. 기존 설치를 갱신하려면 차이를 검토해 병합한다. 기존 AGENTS.md를 건너뛰었다면 공통 원칙도 직접 병합해야 한다. 새 버전이 공개 저장소에 반영된 뒤 Clone해야 이 변경을 받을 수 있다.

스킬이 나타나지 않으면 Codex를 다시 시작한다. `.agents` 쓰기가 차단되면 승인·설정을 우회하지 말고 허용된 터미널 설치 방법을 확인한다. 본 과제 환경이 사전 체험 내용을 보존하는지는 확인이 필요하다.

## 180분 사용 순서
| 경과 | 할 일 |
|---|---|
| 0~20분 | `$env`, `$kickoff`: 실행 환경·Must·기준 입력/출력·핵심 질문 |
| 20~120분 | `$plan`과 구현 요청: 20~30분 단위로 실행·검증·로컬 커밋 |
| 120~150분 | `$verify`: 정상·예외·중요 오답 독립 검산과 수정 |
| 150~170분 | 문서 정리·필요한 경우 `$explain`으로 본인 이해도 점검 |
| 170~180분 | `$wrap`: 저장·제출 미리보기·사용자의 제출물 확정 |

권장 배분이며 실제 남은 시간에 맞춰 조정한다. 후속 서술형 6문항×5분과 준비 대기는 과제 작업 시간과 별개지만 전체 응시는 14:00에 종료된다. 늦게 시작했다면 작업 예산을 줄인다. 별도의 30분 휴식·점검 시간이 보장되는 것이 아니다.

준비 대기는 약 5분 안내와 달리 화면에 최대 10분이 표시되거나 재시도가 발생할 수 있다. 서술형 30분과 준비 대기 여유를 확보하도록 제출물 확정 목표도 앞당긴다.

시작 요청 예:

> 과제 README와 작업 원칙을 읽고, 환경과 요구사항을 점검한 다음 PLAN.md에 계획을 기록하고 핵심 기능 구현까지 진행해줘. 정답과 범위를 바꾸는 질문만 해줘.

계획만 원하면 “계획만 작성해줘”라고 한다. 일반 구현 요청에서는 파일 수·단계 전환·검증마다 재승인을 요구하지 않으며 플랫폼의 실제 권한 요청은 유지한다. 스킬 호출을 모든 단계의 필수 절차로 삼지 않는다.

## 구성과 호출
| 경로 | 역할 |
|---|---|
| AGENTS.md | 공통 실행·검증·기록·도구 경계 |
| templates/REQUIREMENTS.md | 요구사항·가정·업무 담당자 답 |
| templates/DECISIONS.md | 중요한 결정과 이유·대안·한계 |
| templates/PLAN.md | 시간 예산·진행·검증 근거의 단일 기록 |
| install.sh | 기존 파일을 보존하는 설치 |

`$이름`으로 호출한다. 기존 주요 스킬의 명시적 호출 정책은 유지했다. 명시적으로 호출하지 않아도 AGENTS.md의 구현·검증·기록 원칙은 적용된다.

| 스킬 | 호출 | 역할 |
|---|---|---|
| env | 직접 | 필요한 환경만 한 번 확인 |
| kickoff | 직접 | 과제 요구와 핵심 질문 최대 3개 |
| interview | 직접 | 질문 점검 또는 답 기록·영향 반영 |
| plan | 직접 | 계획 저장, 구현 요청이면 이어서 실행 |
| decide | 직접 | 중요한 선택만 중복 없이 기록 |
| verify | 직접 | 위험에 맞는 실행·독립 검산·최소 회귀 검증 |
| wrap | 직접 | 필수 파일·저장·수동 제출 전환 |
| explain | 직접 | 확정 전 이해도 점검, 답안 대필 없음 |
| handoff | 직접 | 세션 교체 때만 짧은 인계 |
| grilling | 요청 내용에 따라 | 허점 점검을 요청했을 때 3분·한 차례 검토 |
| diagnosing-bugs | 요청 내용에 따라 | 막힌 버그에 10분 진단·우회 |
| frontend-design | 요청 내용에 따라 | 업무 화면의 핵심 흐름·가독성 |

## 대회 운영 경계
- 제공 Codex와 허용 모델만 사용한다. 개인 API 키·외부 AI 연결·Astra는 사용하지 않는다.
- 공개 자료 반입은 플랫폼 안의 허용 경로로 한다. 자료·문제·결과물의 반출, Git Push, 제한 우회는 하지 않는다.
- Computer Use는 전 단계 금지다. UI 자동화 대신 터미널·HTTP로 검증하고 플랫폼 Browser 조작·메신저 전송·제출은 사용자가 직접 한다.
- 서버는 0.0.0.0에 바인딩한다. curl 확인 후 사용자가 Browser에서 확인할 때까지 서버·터미널을 유지한다.
- 제출물 확정 후에는 파일 수정과 AI 도움을 중단한다. 후속 서술형은 직접 답하고 최종 완료 화면까지 확인한다.

근거: 참가자 제공 「시험 필수확인사항 브리프」, 「Proctor 설치 및 촬영가이드」, 「사전 체험 및 응시환경 상세 가이드」(2026-10-28 확인). 원문 PDF·시험 문제·개인 링크는 저장소에 포함하지 않는다. 권장 시간 배분과 진단 시간 상한은 이 하네스의 운영 선택이며 대회 의무 규정이 아니다.

## 사전 체험에서 확인할 것
15분·1회 체험에서는 설치·스킬 인식, 짧은 Codex 요청, 작은 서버의 curl 응답과 Browser 수동 확인, 저장·감독 연결·종료 흐름을 우선한다. 실제 제공 런타임·네트워크·권한과 제출 절차는 체험 환경에서 검증해야 한다.
