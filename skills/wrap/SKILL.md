---
name: wrap
description: 제출 전 최종 점검 (실행, 문서, 보안, 정리, 공유 메시지). 사용자가 직접 부를 때만 쓴다.
---

제출 전 최종 점검을 해줘. 각 항목을 실제로 확인하고 체크리스트로 보고해.

- [ ] 과제 README가 정한 제출 문서·파일명이 모두 있고 저장됐는가
- [ ] 처음부터 실행해도 동작하는가: README의 실행 방법을 그대로 따라 실행해서 확인
- [ ] `README.md`: 문제 정의, 주요 기능, 실행 방법, 알려진 한계가 있는가 (없으면 작성)
- [ ] `REQUIREMENTS.md`의 Must 항목이 모두 구현됐는가 (안 된 것은 이유와 함께 명시)
- [ ] `DECISIONS.md`가 최신인가
- [ ] 코드에 API 키, 토큰, 개인정보가 하드코딩되어 있지 않은가 (`grep -rniE 'api[_-]?key|secret|token|password' --exclude-dir=.git --exclude-dir=.agents .`)
- [ ] 디버그용 출력, 쓰지 않는 파일, 실행 중인 백그라운드 프로세스가 정리됐는가
- [ ] 마지막 변경까지 커밋됐는가 (`git status`)
- [ ] 업무 담당자에게 보낼 결과 공유 메시지 초안 (무엇을 만들었는지, **어떻게 받는지(전달 방법·전달할 파일)**, 어떻게 쓰는지, 알려진 한계 중 업무 담당자가 알아야 할 것, 다음 단계 제안. 5줄 이내). 전달 방법을 아직 정하지 않았다면 메시지에 질문으로 넣어

문제가 있는 항목은 고치기 전에 무엇을 고칠지 먼저 알려줘.
