---
name: wrap
description: 제출 전 필수 파일·실행·검증·저장 상태를 점검하고 수동 제출과 후속 서술형 전환을 안내. 사용자가 직접 부를 때 쓴다.
---

과제 작업 종료 10분 전에는 사용자에게 제출을 시작하도록 안내한다. 제출물 확정 전까지만 이 스킬을 수행한다.

- 과제 README의 필수 파일명·경로·내용과 REQUIREMENTS.md의 Must를 대조한다. 누락은 요청 범위 안에서 보완하고 미구현은 이유를 남긴다.
- README의 실행 방법으로 최종 핵심 경로를 한 번 확인한다. 이미 유효한 검증 근거는 PLAN.md를 참조하며 전체 테스트·변형 검증을 반복하지 않는다.
- README 원문 아래에 실행 방법·기능·한계를 적고 중요한 선택의 근거와 미검증이 기록됐는지 확인한다. 새 보고 문서를 중복 생성하지 않는다.
- 비밀정보 후보는 먼저 `rg -l --hidden -i 'api[_-]?key|secret|token|password' -g '!.git/**' -g '!.agents/**' -g '!node_modules/**' -g '!work/**' .`처럼 파일명만 찾는다. rg가 없으면 파일명만 출력하는 대안을 쓴다. 결과 없음과 명령 실패를 구분한다. 매칭 자체를 유출로 단정하지 않고 실제 값은 출력·인용하지 않은 채 점검·마스킹한다. 이 검색만으로 비밀정보·개인정보 전체 검증을 마쳤다고 주장하지 않는다.
- 디버그 파일·임시 산출물·.env가 제출·커밋에 섞이지 않았는지 확인한다. 자체 검증 프로세스만 정리하고 Browser 확인에 필요한 서버·터미널과 플랫폼 관리 프로세스는 유지한다.
- 자신의 변경을 선택해 로컬 커밋하고 git status를 확인한다. Push·외부 공유는 하지 않는다. 시간이 부족하면 커밋보다 필수 파일 저장과 제출을 우선한다.

사용자에게 다음을 짧게 안내한다. AI가 화면을 자동 조작하거나 제출했다고 주장하지 않는다.

1. 에디터의 저장됨·충돌 여부와 필수 경로를 직접 확인한다.
2. 제출 미리보기를 연다. 목록은 일부 파일만 표시할 수 있고 타이머는 계속 흐른다. 고칠 것이 있으면 확정 전에 돌아가 수정한다.
3. 제출물 확정을 직접 누른다. 이후 파일 수정과 AI를 통한 후속 서술형 답변·첨삭·코칭을 중단한다.
4. 준비 대기 뒤 실제 문항 수·시간을 확인하고 본인이 답한다. 전체 종료 시각은 14:00이다.
5. 마지막 답안 처리 후 완료 화면의 제출 ID·시각·파일 수·크기를 확인한다. 제출물 확정만으로 최종 완료라고 판단하지 않는다.

결과는 `제출 준비 상태 / 남은 필수 조치 / 미검증·한계`만 보고한다. 외부 전달 메시지는 만들지 않는다.
