AGENTS.md를 읽고 사용자가 요청한 범위 안에서 수행한다. 이 스킬을 실행한다고 다른 스킬을 전부 호출하지 않는다. 진행 중인 과제면 기존 기록과 변경된 파일부터 확인해 이어간다.

## 시작: 목표와 기준 입력
1. 과제 README와 제공 파일의 구조·작은 표본을 확인한다. 기존 코드·런타임을 활용하고 필요한 도구만 점검한다. 먼저 구현하지 말고 필수 요구·제출 파일·업무상 성공 기준을 추출한다.
2. 모든 필수 요구에 R-번호를 부여하고 출처·기대 동작을 REQUIREMENTS.md에 기록한다. 플랫폼 지정 양식이 있으면 그것을 사용한다. 대표 입력 하나와 기대 출력·예외 하나를 확보한다. 담당자에게 물을 핵심 질문은 한 번에 최대 3개만 초안으로 주고 전송은 사용자가 한다.
3. PLAN.md에 문서 경로·시각 기준·작업 종료·확정 목표·필수 요구별 구현/검증 표를 둔다. 기본 준비 여유 15분을 사용할 때 목표는 `min(작업 종료, 한국시간 13:15)`이고 제출 준비는 그보다 10분 전이다. 이는 하네스의 보수적 권장값이다. 이미 그 시각을 지났다면 과거 목표를 고집하지 말고 즉시 남은 필수 조치를 줄여 제출을 우선한다. 실제 화면 안내가 우선이며 지연을 보장할 수 없다.

## 구현: 최소 흐름부터 확장
4. 대표 입력→핵심 처리→사용 가능한 출력이 실제로 돌아가는 가장 작은 기능을 만든다. UI 장식·범용 프레임워크·새 MCP 설정은 뒤로 미룬다. 이 첫 실행으로 데이터 형식·런타임·사용 흐름의 위험을 먼저 확인한다.
5. 나머지 Must를 가치·위험·의존성 순서로 붙인다. 각 단위에서 실행·검증하고 관련 표와 결정만 갱신한다. 답변이 바꾼 기준은 출처를 기록하고 영향을 받는 코드·테스트를 수정한다. 사용자가 정한 목표를 임의로 축소하지 않는다.
6. 중요 오답 하나를 별개 기준으로 검산한다. 예: 빈 값·중복·경계 날짜·단위·분모 중 과제에 해당하는 위험만 선택한다. 이 목록 전체를 검사할 필요는 없다. 시간이 부족하면 선택 기능부터 버리고 필수 실패를 드러낸다.

## 마무리: 실행 가능한 제출물
7. 남은 30분 또는 핵심 Must 완성 시 요구사항 표의 누락·실패·미검증을 확인한다. 실행 방법으로 최종 통합 경로를 확인하고 UI는 사용자에게 플랫폼 Browser에서 수동 확인하도록 안내한다.
8. 실행 방법·주요 선택·독립 검증·알려진 한계를 과제 지정 문서에 정리한다. 요청하거나 필요할 때만 이해도 질문을 짧게 제시한다. 반복 보고·모범 답안 생성은 하지 않는다.
9. 확정 목표 10분 전에는 필수 경로·파일 저장·충돌 여부를 확인하고 사용자에게 제출 미리보기를 열도록 안내한다. 미완성 항목은 명시한다. 확정 뒤 AI 작업을 중단하고 최종 서술형·완료 화면 확인은 사용자가 진행한다.

사용자가 도중에 상태를 물으면 `현재 실행되는 것 / 남은 Must / 가장 큰 위험 / 다음 행동`만 답하고 작업을 이어간다. 필수 결정이 막혔을 때만 질문하며 단순 단계 전환에 승인을 요청하지 않는다.
