---

`check`는 질문 점검, `record`는 답 기록이다. 접두사가 없어도 질문 초안인지 받은 답인지 명확하면 해당 작업을 한다. 구분이 안 될 때만 한 번 묻는다. REQUIREMENTS.md의 관련 항목과 기존 답만 읽는다.

## check
- 이미 받은 답·중복·막연함·한 문항에 섞인 질문을 점검한다. 지금 구현에 영향을 주는 질문 최대 3개를 고르고 바로 보낼 수 있는 짧은 수정안을 제시한다.
- 실제 입력 예시·기대 출력·경계 사례를 요청하면 답이 명확해지는지 살핀다. 질문 수를 채우려고 새 질문을 만들지 않는다. 전송은 사용자가 직접 한다.

## record
- 제공된 답을 REQUIREMENTS.md의 인터뷰 기록과 관련 Must·가정·미해결 질문에 반영한다. 없던 답이나 시각을 만들지 않고 중요한 원문만 짧게 인용한다.
- 답으로 바뀐 핵심 규칙·범위·스택은 DECISIONS.md에 바로 기록한다. 기록 여부를 다시 묻지 않는다.
- 기대값·테스트·구현에 미치는 영향을 짧게 알린다. 기존 구현 요청 범위면 필요한 수정과 관련 검증까지 이어서 수행한다. 답 기록만 요청했으면 기록과 영향 보고에서 마친다.
- 필수 범위 충돌·새 데이터 사용 권한처럼 사용자의 결정이 필요한 경우만 확인한다. 전체 문서와 diff를 반복 출력하지 않는다.
