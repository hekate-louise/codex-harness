AGENTS.md를 따르고 사용자가 요청한 범위 안에서 수행한다. 이 스킬을 실행한다고 다른 스킬을 전부 호출하지 않는다. 진행 중인 과제면 기존 기록과 변경된 파일부터 확인해 이어간다.

## 시작: 목표와 기준 입력
1. 과제 README와 제공 파일의 구조·작은 표본을 확인한다. 먼저 구현하지 말고 필수 요구·제출 파일·업무상 성공 기준을 뽑는다.
2. 모든 필수 요구에 R-번호를 붙이고 출처·기대 동작을 REQUIREMENTS.md에 적는다. 대표 입력 하나와 기대 출력·예외 하나를 정한다. 업무 담당자에게 물을 핵심 질문은 한 번에 최대 3개만 초안으로 주고, 전송은 사용자가 한다. 사용자 환경·입력·출력 질문을 첫 질문에 넣는다.
3. 사용자에게 시작 시각과 마감을 확인해 PLAN.md에 시각 기준·확정 목표·필수 요구별 구현/검증 표를 둔다. 이미 목표 시각을 지났다면 남은 필수 조치를 줄여 제출을 우선한다.
4. 범위와 계획을 짧게 보여 주고 **사용자 승인을 받은 뒤** 구현을 시작한다.

## 구현: 최소 흐름부터 확장
5. 대표 입력→핵심 처리→사용 가능한 출력이 실제로 돌아가는 가장 작은 기능을 만든다. UI 장식·범용 프레임워크는 뒤로 미룬다. 이 첫 실행으로 데이터 형식·런타임·사용 흐름의 위험을 먼저 확인한다.
6. 나머지 Must를 가치·위험·의존성 순서로 붙인다. 단위마다 실행·검증하고 `한 것 / 근거 / 사용자가 정할 것`을 보고한다. 답변이 바꾼 기준은 출처를 적고 영향을 받는 코드·테스트를 고친다. 사용자가 정한 목표를 임의로 줄이지 않는다.
7. 중요 오답 하나를 별개 기준으로 검산한다. 빈 값·중복·경계값·단위 중 과제에 해당하는 위험만 고른다. 시간이 부족하면 선택 기능부터 버리고 필수 실패를 드러낸다.

## 마무리: 실행 가능한 제출물
8. 남은 30분 또는 핵심 Must 완성 시 요구사항 표의 누락·실패·미검증을 확인한다. 실행 방법으로 최종 통합 경로를 확인하고, 화면은 사용자가 직접 확인하도록 포트·경로와 확인할 동작을 안내한다.
9. 실행 방법·주요 선택·독립 검증·알려진 한계를 과제 지정 문서에 정리하고, 업무 담당자에게 보낼 결과 공유 메시지 초안을 만든다. 이해도 질문은 요청할 때만 짧게 내고 모범 답안은 쓰지 않는다.
10. 확정 목표 10분 전에는 필수 경로·파일 저장·커밋을 확인하고 사용자에게 제출을 안내한다. 미완성 항목은 명시한다. 확정 뒤에는 AI 작업을 멈춘다.

사용자가 도중에 상태를 물으면 `현재 실행되는 것 / 남은 Must / 가장 큰 위험 / 다음 행동`만 답한다.
